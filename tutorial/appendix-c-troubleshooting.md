# 付録 C: よくあるトラブル集

学生からの質問頻度の高い順にまとめました。
症状 → 原因候補 → 対処の3点セット形式です。

## サーボ系

### Q1. サーボがブルブル震えるだけで動かない

**原因候補**
1. GND が Arduino と PCA9685 とサーボ電源で共通になっていない
2. `SERVOMIN` / `SERVOMAX` が物理可動範囲を超えている
3. サーボの停動状態（機構が引っかかっている）

**対処**
1. ジャンパで GND を 1 本足してみる（共通化）
2. `examples/01_single_servo/01b_calibration.ino` で安全な値を再測定
3. 機構を手で動かして引っかかりを除く

### Q2. 1個だけ全然動かない

**原因候補**
1. そのチャンネルの PWM 端子配線ゆるみ
2. サーボ自体の故障（特に MG996R は突入電流で壊れやすい）
3. キャリブレーション値が初期値のまま（`pwmMin == pwmMax`）

**対処**
1. ch 0 など別チャンネルに挿し替えて試す
2. 別の正常サーボに交換して試す
3. キャリブレーション構造体を確認

### Q3. 電源を入れた瞬間にサーボが「ガッ」と最大角まで振れる

**原因候補**
1. 電源 ON 時に PCA9685 が初期化されるまでの間、出力が不定
2. setup() 内で初期角度を送る前に時間がかかっている

**対処**
1. 電源 ON → スケッチが `setup()` を抜けるまで、サーボのアームが
   危険な位置に行っても物理的に当たらないよう **組立段階で配慮**する
2. `setup()` の最初の方で `pwm.setPWM(ch, 0, 中立位置)` を全 ch に送る
3. 起動時はサーボに電源を入れない（FET スイッチで遅延 ON するなど高度な手法も）

### Q4. ジリジリ音は鳴るけど動かない

**原因候補**
1. 電源容量不足（電圧降下でサーボが息継ぎ）
2. サーボに与えているパルス幅が「動こうとして動けない」位置
3. 機構の引っかかり

**対処**
1. **付録 A** の電源見直し
2. パルス幅を中立（375 カウント程度）に戻して鳴き止むか確認
3. アームを外して負荷ゼロで動くか確認

## I²C / 通信系

### Q5. `pwm.begin()` の後でハングする

**原因候補**
1. PCA9685 が応答しない（電源 or 配線）
2. Wire ライブラリが他で使われている

**対処**
1. **付録 B** の I²C スキャナで `0x40` が見えるか
2. 別の I²C デバイスを外して切り分け

### Q6. 動作中に時々サーボが暴れる

**原因候補**
1. I²C 通信ノイズ（長い配線、高負荷の隣接動作）
2. 電源リセット（ブラウンアウト）
3. メモリ破壊（配列の範囲外アクセス）

**対処**
1. SDA/SCL は 30 cm 以下に。短いほど安定
2. 電源を見直し（付録 A）
3. `legs[NUM_LEGS]` のアクセスが範囲内か Serial で確認

## ソフトウェア / IK 系

### Q7. IK が NaN を返す

**原因候補**
1. `acosf` の引数が ±1 を超えている
2. 距離が L1+L2 を超えている / |L1-L2| 未満

**対処**
1. `constrain(x, -1.0f, 1.0f)` を入れる
2. 入力 (x, y, z) を Serial で確認、可動範囲内に収まる軌道に修正

### Q8. 歩こうとするけど後ろに進む

**原因候補**
1. スタンス期の足先 x が逆向き
2. 左右の `side_sign` が逆

**対処**
1. `footTrajectory` の x 計算式を反転 (`stride/2 - stride*p` ↔ `-stride/2 + stride*p`)
2. ロボットを後ろから見て前進するなら `side_sign` を全部反転

### Q9. 1本だけ脚が逆向きに動く

**原因候補**
1. 左右で取り付けがミラーになっているのに `direction` が同じ
2. ヨーサーボの取り付け角が他と違う

**対処**
1. 左脚は `direction = -1`、右脚は `+1` に揃える
2. キャリブレーション工程をやり直す

## 機構 / 動作系

### Q10. 4本中 1〜2本だけ浮いている

**原因候補**
1. ロボットの組立精度（左右対称になっていない）
2. `z_default` が脚の長さに対して合っていない

**対処**
1. 床に置いて、4 脚すべてが地面に着くよう機構を調整
2. `z_default` を 5 mm 単位で増減して試す

### Q11. すぐ転倒する

**原因候補**
1. トロットでスタンス時間が短すぎ
2. `step_height` が大きすぎて重心が上下に揺れる
3. 足先のグリップ不足

**対処**
1. クロール（duty=0.75）に切り替え
2. `step_height` を 10〜15 mm まで下げる
3. 足先にゴムキャップやヒシテープ

### Q12. 1サイクル目だけうまく歩くが、2サイクル目から崩れる

**原因候補**
1. `phase_global` のラップアラウンド処理ミス
2. サーボへの命令が間に合っていない（`delay(20)` が短い）

**対処**
1. `while (phase_global >= 1.0f) phase_global -= 1.0f;` を確認
2. ループ内の処理時間を `millis()` で計測

## 電源系

### Q13. 動かすと Arduino がリセットする

**原因候補**
1. サーボ電源と Arduino 電源が共通で、サーボ突入電流で電圧が落ちる

**対処**
1. **付録 A** の通り、サーボと Arduino の電源を分離
2. それでもダメなら大容量コンデンサ追加

### Q14. しばらく動かすとサーボが熱くなる

**原因候補**
1. 機構が常に「無理な姿勢」を要求している
2. サーボへの電圧が高すぎ
3. 単純に長時間連続駆動

**対処**
1. IK の解が常に限界角に近い → リンク長 / 取付位置を見直す
2. 定格電圧に戻す
3. 連続動作 1 分 → 休憩 30 秒のような運用ルール

## それでも解決しない時は

- 「症状を 1 文で書く」「直前に変えた点を箇条書き」「Serial 出力を貼る」
  の3点セットで TA / 講師に相談
- スマホで現象を **動画**で撮ってから持ってくると話が早い
